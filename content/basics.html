Базовые настройки интерфейса (Для чайников)

Тут я разберу интерфейс которым в целом пользуюсь лично сама, дабы вы поняли куда тыкать и иметь памятку под рукой.

Розетка. Подключение.


1. Тут написана версия вашей SillyTavern (рекомендую раз в два-три месяца на всякий случай обновлять).
2. Тут ваши недавние чаты с ботами. Стрелочка ниже раскрывает больше недавних чатов.

Основная вкладка подключения, я называю ее "Розетка". Внимательно выбираем API.

Во вкладке API выбираем именно CHAT COMPLETION. Все пресеты и ваши апишки будут совместимы лишь с ним.

Источник для "Chat completion". Тут выбираем провайдера. Важно понимать разницу:
1. Есть провайдеры которые можно выбрать и напрямую к ним подключиться (Openrouter, Google, Deepseeek и т.д.)
2. Есть провайдеры, которые подключаются лишь через кастомный эдпоинт.
Чтобы понять какой подключать, изучайте документацию своего провайдера, где-то точно есть адрес для кастомных эдпоинтов. Это будет не личная рекомендация или реклама, просто покажу на примере провайдера Literouter.

В документации указан такой URL. Он и подходит (некоторые провайдеры также могут иметь зеркала, за таким лучше следить лично у провайдеров в соц сетях по типу Telegram чатом или Discrod каналов).
Вот так по итогу выглядит кастомный эдпоинт с URL от провайдера. Больше ничего добавлять не надо.

Прокси. Некоторые провайдеры поддерживают проксирования через официальных провайдеров по типу Google, Claude, Deepseek.

1. Название для прокси. Вводите что хотите, так как по большей части это удобство для вас, если имеете нескольких провайдеров.
2. Тут вставляете URL провайдера.
3. Тут вставляете конкретно ключ от провайдера, откуда берете URL. Однако некоторые URL могут являться зеркалами, не имея конкретно API ключа (такими не рекомендую пользоваться, обычно за такие вещи выдают баны аккаунтам. Не раз сталкивались с URL Софией и банами от Google).

Когда настроили прокси, "ОБЯЗАТЕЛЬНО" нажмите на данный документ, чтобы сохранить прокси. Иначе все сбросится.
Теперь рассмотрим как правильно вставлять ключ. Необходимо это делать через "Менеджер ключей". Как видим на скриншоте, написано что "ключ сохранен", если у вас отображается ваш API ключ, значит вы неправильно вставили его.



1. Сюда вы вставляете API ключ.
2. Сюда вы вводите название для API ключа, тут опять же для вашего удобства.

Подключение и выбор модели. Можете сразу нажать подключение, иногда это необходимо чтобы отобразились все модели от провайдера.



Если вы подключаетесь к провайдеру у которого есть бесплатные модели, выбирайте внимательно. Просматривайте верное id модели и как она написана у провайдера. Иногда необходимо скопировать и вручную вставлять, чтобы подключить к конкретно модели. У других провайдеров есть приписка у free моделей.
На данный момент провайдер Electron Hub не предоставляет бесплатных моделей.

Проверка подключения. Нажмите на "Тестовое сообщение" и получите зеленое зеленое уведомление о подключении к провайдеру.
ВАЖНО: Для провайдер Claude чтобы подключиться к модели (например вы делаете прокси), необходимо как раз верифицировать ключ через "Тестовое сообщение".

Постобработка. Для полной информации переведу официальную документацию данной плашки.

Некоторые конечные точки могут накладывать определенные ограничения на формат входящих запросов, например, требовать только одно системное сообщение или строго чередовать роли.
SillyTavern предоставляет встроенные преобразователи командных строк, которые помогают соответствовать этим требованиям (от наименее до наиболее строгих):
1. "Отсутствует". Никакой явной обработки не применяется, за исключением случаев, когда это строго требуется API.
2. "Объединение идущих подряд сообщения с одной ролью."
3. "Semi-strict" - чередование ролей" — объединение ролей и разрешение только одного необязательного системного сообщения.
4. "Strict" - чередовать роли, сначала пользователь" — объединение ролей, разрешение только одного необязательного системного сообщения и требование, чтобы сообщение пользователя было первым.
5. "Только одно сообщение пользователя" — объединение всех сообщений от всех ролей в одно сообщение для пользователя.
Режимы «Объединение», «Semi-strict» и «Strict» дополнительно удаляют любые вызовы инструментов из запроса, если не выбран вариант «с инструментами». Это полезно для API, которые не поддерживают вызовы инструментов, а ваши существующие запросы содержат вызовы инструментов. Менее строгие параметры не влияют на более строгие конечные точки, реализованные в SillyTavern, за исключением параметра "Custom OpenAI-compatible"; при некорректном запросе параметр Custom может выдать ошибку.
Приведу пример для чего можно было использовать: существовал такой провайдер как MegaLLM, на модели Gemini 3 pro, много пользователей жаловались на "нечтение" лорбуков. Все решалось постобработкой "Semi-strict".

Это не значит, что если у вас проблемы с лорбуком, то данные функция вас спаасет. Все-таки изучите гайд на лорбуки, прежде чем тыкать постобработку.

После того как подключили профиль, проверили его работу, сохраните обязательно его. Также можете сразу включить галочку для автоматического подключения при входа в SillyTavern, если верите в непадение провайдера.
